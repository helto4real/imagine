Generate or upscale images through Imagine API profiles. First call list_profiles, then describe_profile for the chosen profile. Choose qwen for standard generation and editing, quick-draft for Turbo previews, or a specialized profile from the catalog. Read and apply its full prompt_guidance to parameters.prompt. If has_default_prompt is true, omit prompt to use the stored profile prompt unless the user requests an override. Pass only overrides in parameters; nested objects merge recursively and lists replace completely. Select the profile before registering references; IDs belong to that profile and must be supplied in order. For image_upscale, register exactly one image and pass optional max_side and seed. max_side is the longest image edge in pixels: minimum 256, maximum 4096, in multiples of 32. For image_upscale, 3200 is only the default when max_side is omitted, not the maximum. For profiles with random seed defaults, omit seed for a fresh seed per image or provide an integer for a fixed seed. Results contain the resolved seed. The nsfw flag is an opt-in LoRA switch, not a content label. Set parameters.nsfw=true only if nsfw_available is true and the user explicitly requests enabling the NSFW mode, flag or LoRA for this image or batch, e.g. 'enable NSFW mode' or 'nsfw=true'. Requests for NSFW, nude, erotic or explicit content, including 'make an NSFW image', do not authorize this switch. Never infer activation from prompts, prompt guidance, references or earlier jobs. Without a clear activation request, omit nsfw or set false and proceed with the requested image. It is independent of the selected profile and draft/standard quality. When multiple images are needed, prefer generate_batch: it is the most efficient way to avoid repeated GPU switching and slow LLM reloads. Prepare all items before calling it. Choose a unique job_id before generate or generate_batch. If a call times out, use get_job with that same ID; do not start another generation. Images are local files. Only an active LLM request triggers GPU restoration. After every successful image, including successful items in a partial batch, always copy its temporary path to a unique persistent local file in the client project. Verify only file integrity: the destination must be a regular file whose byte size and SHA-256 match the returned bytes and sha256. Compute these from the destination file; do not merely echo the metadata. Do not open, render, visually inspect or analyze the image, or compare it with the prompt, as part of verification. Then call confirm_saved with job_id and images containing image_id, saved_path (absolute destination path), bytes and sha256 measured from each verified copy. During an active session, confirm_saved removes only confirmed temporary images. Session shutdown removes all remaining temporary images. If copying or verification fails, do not confirm; retain the temporary files and report the error. Retry a lost confirmation with the same arguments. Report the persistent local paths, not temporary paths. A completed batch can be confirmed in subsets. Output image_ids identify delivery results; register_image returns separate reference IDs.

Session privacy: temporary images, reference IDs and job history exist only during the current Imagine/proxy session. Copy and confirm successful images promptly; stopping Imagine or the proxy discards unconfirmed images and reference previews. If Imagine is locked or unavailable, ask the user to unlock it in the server terminal. Never ask for passwords or YubiKey PINs in chat or tool arguments. After restart, register references again and use new job IDs.
