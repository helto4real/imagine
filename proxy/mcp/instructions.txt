Generate or upscale images through Imagine API profiles. First call list_profiles, then describe_profile for the chosen profile. Choose qwen for standard generation and editing, quick-draft for Turbo previews, or a specialized profile from the catalog. Read and apply its full prompt_guidance to parameters.prompt. If has_default_prompt is true, omit prompt to use the stored profile prompt unless the user requests an override. Pass only overrides in parameters; nested objects merge recursively and lists replace completely. Select the profile before registering references; IDs belong to that profile and must be supplied in order. For image_upscale, register exactly one image and pass optional max_side and seed. max_side is the longest image edge in pixels: minimum 256, maximum 4096, in multiples of 32. For image_upscale, 3200 is only the default when max_side is omitted, not the maximum. For profiles with random seed defaults, omit seed for a fresh seed per image or provide an integer for a fixed seed. Results contain the resolved seed. The nsfw flag is an opt-in LoRA switch, not a content label. Set parameters.nsfw=true only if nsfw_available is true and the user explicitly requests enabling the NSFW mode, flag or LoRA for this image or batch, e.g. 'enable NSFW mode' or 'nsfw=true'. Requests for NSFW, nude, erotic or explicit content, including 'make an NSFW image', do not authorize this switch. Never infer activation from prompts, prompt guidance, references or earlier jobs. Without a clear activation request, omit nsfw or set false and proceed with the requested image. It is independent of the selected profile and draft/standard quality. When multiple images are needed, prefer generate_batch: it is the most efficient way to avoid repeated GPU switching and slow LLM reloads. Prepare all items before calling it. Choose a unique job_id before generate or generate_batch. If a call times out, use get_job with that same ID; do not start another generation. Images are local files. Only an active LLM request triggers GPU restoration. Imagine has already saved every successful image under the verified encrypted persistent_root. Report the returned saved_path/path directly; do not copy the image into a delivery cache or another folder. confirm_saved is an optional backwards-compatible acknowledgement of that same published path and metadata; it never copies or deletes files. Do not open, render, visually inspect or analyze images, or compare them with prompts, as part of delivery acknowledgement. Output image_ids are delivery identifiers, not registered reference IDs.


Session privacy: registered original paths, RAM-only normalized previews, reference IDs and job history exist only during the current Imagine/proxy session. Stopping either session discards that RAM state; original references and Imagine-generated persistent outputs remain untouched. After restart, register references again and use new job IDs. If Imagine or the verified media destination is unavailable, ask the user to make it available. Never ask for passwords or YubiKey PINs in chat or tool arguments.

Original references stay at their selected paths. All generated media is saved by Imagine under the returned verified encrypted persistent_root. MCP creates no disk previews, reference copies, delivery copies or temporary media cache. Report the published local paths directly. If a container cannot access that same host path, report the limitation; do not use an unverified path mapping. Historical cache files are not scanned or deleted at startup or shutdown.

The video profile never enables the image nsfw switch. Report project path, save status and final video path; automatic acceptance is not a visual review.
