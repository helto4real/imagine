## Result and acceptance boundary

The local source reference is captured and fingerprinted. The inventory includes all Python definitions in the selected base inference source trees, conditional registries, built-in node contracts and dependency declarations. This is a **static inventory**, not a claim that every definition is inference, every conditional feature is active, or any capability has been ported or run.

The reference is ComfyUI `ba994879b88d0ebd9950b1e5c1e923d928f216ba`, local Kitchen distribution `0.2.37`, and the installed Torch whose source reports `2.13.0+cu130`, CUDA `13.0`, revision `cf30153c4c131c8164ee7798e5022d810682e2cb`. Torch distribution metadata reports `2.13.0`; both identities are retained rather than normalized into an assumed wheel identity.

Initial target: Arch Linux and RTX 4070 Ti SUPER, as specified by Tomas. Local inference only: cloud/hosted inference services are explicitly excluded. Package metadata records system CUDA `13.4.2-1`, which is distinct from Torch's `13.0` build. No change or compatibility assumption is made between them. GPU identity is user-specified, not device-probed. Installed kernel/driver packages are recorded without inspecting a running driver or service.

**Stage 0 source locking and inventory are complete as a reviewable deliverable.** Reference source/binary identities, approved scope, dependency conditions and provenance evidence are recorded. This is not acceptance of a built engine: standalone linkage, rebuilt-kernel fidelity and model/runtime parity remain later-stage verification gates. No deviations are approved or introduced. No engine implementation, package installation, engine selection, runtime inspection, model loading or GPU execution occurred.

### Registry findings that must survive the port

- The model registry contains 105 entries; these are not the total number of checkpoint variants or components. The full ordered list is preserved in the design and source assignment.
- Sampling has 42 k-diffusion sampler names plus `ddim`, `uni_pc`, `uni_pc_bh2`, and nine scheduler registrations. Advanced core node operations and manual schedules remain separately inventoried.
- Quantization includes FP8 E4M3/E5M2, NVFP4, conditional MXFP8, tensorwise INT8, ConvRot W4A4, asymmetric W4A8 and W6A8. Registry updates and layout registrations are retained with predicates; installed support is not equated with active dispatch.
- `weight_adapter/__init__.py` lists six adapters in `adapters`, but leaves GLoRA and BOFT disabled in `adapter_maps`. Preserve this distinction rather than enabling or dropping them globally.
- Kitchen default backend priority is subsequently modified by ComfyUI/runtime-specific conditions. Triton is installed (`3.7.1`), but ComfyUI source makes it opt-in. CUDA and HIP native Kitchen objects are fingerprinted; only the approved machine's applicable paths belong to initial acceptance.
- `comfy_aimdo==0.5.6` is a real core dependency, not an optional optimization we may omit. Its native bridge and memory semantics require the same analysis as Kitchen.

## Dependency interpretation

`dependencies.json` separates declared requirements, installed packages, import roots and missing alternatives. Markers/extras are preserved but not evaluated. The fingerprint closure is a conservative union of static imports and installed transitive requirements, including non-Linux and optional alternatives where installed. This over-inclusion protects identity; it does not expand production scope.

Installed versions include Kitchen `0.2.37`, AIMDO `0.5.6`, TorchVision `0.28.0`, TorchSDE `0.2.6`, Transformers `4.57.6`, Tokenizers `0.22.2`, SafeTensors `0.8.0`, SageAttention `2.2.0`, NumPy `2.3.5` and SciPy `1.17.1`. Every declared ComfyUI requirement has an installed distribution. That does not prove importability, version-constraint satisfaction on every marker branch, or hardware availability.

Frontend/templates/docs, HTTP, database and asset-manager packages remain visible because they occur in the local base requirements. Their metadata is part of the observed environment, not a requirement to ship ComfyUI UI/server/history functionality in the Rust engine.

Unmatched roots are explicitly retained. `app`, `execution`, `protocol`, `server`, `comfyui_version` are local boundary helpers (supplementary source captured); `comfyui_manager` is manager-gated; `cublas_ops`, `flash_attn`, `sageattn3`, `spandrel_extra_arches`, `trimesh`, `xformers` are missing/conditional paths requiring branch-specific source review. `torch_directml`, `torch_mlu`, `torch_npu` relate to non-target devices. None is silently installed, replaced or discarded. In particular, missing `trimesh` in a Hunyuan3D path is a capability-validation gap, not permission to drop that model.

## Verification and reproduction

Run from the Imagine checkout:

```sh
python3 -B design/reference-local/tools/capture.py verify
python3 -B design/reference-local/tools/native_linkage.py verify
```

Verification rehashes all locked files and artifacts and compares the main preserved source archive. It never imports ComfyUI/Kitchen/Torch, initializes CUDA or reads model/runtime directories. Supplemental archive members are additionally checked during this task's archive-integrity check.

`capture.py capture` refuses to overwrite an existing reference lock; `supplement.py` refuses to overwrite its source supplement. `index.py` rebuilds only the derived semantic index from the frozen source archive. Reference changes require explicit approval. The capture is source-only and intentionally does not execute the reference interpreter, pip hooks or extension code.

Validation performed: successful full fingerprint/artifact verification, source-archive member hash checks, static inventory/count reconciliation, local Markdown-link checks and whitespace checks. These checks establish capture consistency, not a successful inference port. No escalation was used in the initial source capture; later approved source downloads used network sandbox escalation. No commit or push was requested.

Subsequent authorized provenance work: public Kitchen/AIMDO repositories were fetched using `gh-axi` with network sandbox escalation, placed under the isolated development root and checked out at the pinned revisions above. No fetched code was executed and no package was installed. Source files were compared against the original local manifest; frozen source fingerprints and capture archives were retained unchanged. Native source archive member hashes and generated AIMDO version evidence were checked. At that point submodules and LibTorch source acquisition were still pending; the final Stage 0 pass below supersedes that acquisition status. Build/runtime acceptance remains unrun, with no substitutions adopted.

Final Stage 0 pass: PyTorch/ATen, tch-rs, Kitchen CUTLASS/FlashAttention, funchook and distorm were fetched via `gh-axi` and checked out at their exact locked revisions. Source fingerprints were reconciled with Git blob IDs. ELF dependencies/compiler comments were read with `readelf`, without loading any library. Both reference and additional ELF fingerprints were verified; scope/marker counts, archive hashes and local document links were checked. No engine build, fixture generation or inference was performed. No deviation needs approval. Work stops at the Stage 0 boundary; starting Stage 1 requires Tomas's instruction.
