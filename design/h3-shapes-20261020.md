## Admission, transport and limits

The same shared geometry validation governs UI, job admission and worker wire v2.
The selected shape reaches latent allocation, memory estimates, decoding,
stream validation, FFV1/PCM Matroska export, storage metadata and UI preview.
Invalid geometry is rejected before model construction. The v1 request profile
is accepted only for its original fixed shape; v2 enables geometry selection.
Old wire-v1 workers cannot be paired with this server.

The product keeps a 4 MiB per-frame wire bound and a 2 GiB decoded AV bound.
This permits all 1 MP presets at 15 seconds; larger combinations may be rejected.
The bound is not a total process RAM limit: decoding/copying can use several
buffers. It is not a VRAM-fit guarantee. The UI warns for nondefault profiles
and durations outside the source's approximate 5–15-second training range.
Model memory estimates scale with geometry; actual larger-profile VRAM needs
remain untested and may fail with out-of-memory.
